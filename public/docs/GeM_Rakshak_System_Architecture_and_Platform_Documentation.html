GeM-Rakshak Technical Architecture Dossier Section 1: Executive Summary & Context

1. Executive Summary & Problem Context

1.1 The High-Stakes Public Procurement Challenge

The Government e-Marketplace (GeM) processes over ₹4,00,000 Crores in annual procurement across Central Ministries, State Governments, and Central Public Sector Enterprises (CPSEs). For complex engineering and petrochemical tenders (such as those floated by CPCL, IOCL, and ONGC), technical bid evaluation requires verifying hundreds of pages of submitted documentation per bidder: Chartered Accountant net-worth certificates, GST returns, MSME Udyam credentials, past performance certificates, and statutory declarations.

Traditionally, this technical scrutiny is conducted manually by procurement officers, leading to severe operational risks:

  • Evaluation Delays: Scrutinizing complex tenders takes 3 to 6 weeks, stalling critical infrastructure projects and capital expenditure.
  • High Sophistication Fraud: Bidders submit forged UDIN/CA turnover certificates, fabricated GSTR-3B tax receipts, and manipulated PDF text where visual numbers have been doctored using desktop publishing tools.
  • The QR Code Vulnerability: Many certificates include valid-looking QR codes. However, procurement officers lack the automated tools to cross-reference whether the visual text matches the encoded cryptographic payload, enabling fraudulent bids to pass visual checks.
  • Bidding Cartels & Cover Bidding: Syndicates submit multiple bids through sister entities with common directors, shared IP addresses, identical bank guarantee branches, and clustered pricing to rig L1/L2 outcomes.

1.2 SIH Problem Statement 26100 Objectives

SIH Problem Statement 26100 Mandate
"Develop an AI/ML-based platform for automated evaluation of technical bids and verification of documents submitted in Government tenders, integrating computer vision, multi-gateway reconciliation, and collusion detection to ensure complete transparency, non-discretionary compliance, and auditability."

GeM-Rakshak was engineered specifically to solve this challenge. It provides an autonomous, multi-tenant vigilance platform that ingests raw tender submissions, performs deep neural document forensics, validates credentials in real-time across five statutory government gateways, uncovers hidden bidder cartels via network graph analytics, and generates legally binding, immutable CVC audit dossiers in less than 30 seconds.

2.2 Core Architectural Principles

  • Zero-Trust Document Verification: Every document submitted is treated as unverified until cross-referenced across statutory government APIs.
  • Explainable AI (XAI): Black-box decisions are strictly prohibited under CVC guidelines. Every disqualification or compliance score is backed by granular, human-readable clause citations and visual evidence diffs.
  • Tamper-Proof Auditability: Evaluation results, API response snapshots, and forensic verdicts are cryptographically hashed using SHA-256, creating an immutable log for statutory vigilance inquiries.
  • Dynamic Entity Tenancy: Unified multi-PSU data model allowing instant contextualization across CPCL, IOCL, ONGC, GAIL, and BPCL procurement guidelines.

3.4 Module 4: Cartel & Collusion Radar (/cartel-radar)

Uncovering anti-competitive agreements, bid rigging, and cover bidding as prohibited under Section 3(3) of the Competition Act, 2002.

  • Digital Footprint Correlation: Identifies bids originating from identical public IP subnets, shared MAC hardware addresses, or identical browser user-agent fingerprints.

GeM-Rakshak Technical Architecture Dossier Section 4: QR Code Forensics Engine

4. Technical Deep Dive: The QR Code Forensics Engine

4.1 The Threat Model: The Hidden Vulnerability of Visual QR Codes

In modern public procurement, CA certificates, GST registration certificates, and MSME Udyam receipts routinely display a quick-response (QR) code in the document header or footer. Fraudulent syndicates exploit a critical blind spot in traditional manual evaluation:

The "Visual Decoupling" Attack Vector
Fraudulent bidders create a legitimate certificate for a small turnover (e.g. ₹2.10 Cr) that contains an authentic QR code generated by the portal. They then use PDF editing tools to visually alter the printed text on the page to read ₹12.50 Cr, qualifying for high-value tenders. Because human officers assume the presence of a crisp QR code implies authenticity, the fraud passes scrutiny unnoticed.

4.2 GeM-Rakshak Dual-Verification Forensic Algorithm

GeM-Rakshak eliminates this vulnerability by executing a real-time, automated dual-verification protocol:

[SUBMITTED PDF DOCUMENT] | +---------------------------------------+ | | v v [EXTRACT VISUAL TEXT via OCR] [LOCATE & DECODE QR CODE] - Declared Turnover: ₹12.50 Cr - Raw Payload Scanned - UDIN: 24089123AAAA01 - Embedded Turnover: ₹2.10 Cr - Entity: Apex Heavy Engg - Embedded Entity: Apex Small Spares | | +-------------------+-------------------+ | v [AUTOMATED PAYLOAD DIFF ENGINE] | +-------------------+-------------------+ | | [VALUES MATCH] [DISCREPANCY DETECTED] | | [GATEWAY VALIDATION] [NEURAL VERDICT: CRITICAL FRAUD] | - Forensic Heatmap Generated [STATUS: PASS] - Status: IMMEDIATE DISQUALIFICATION - Referral: CVC Vigilance Wing

4.3 Forensic Sandbox Interactive Capabilities

  • Raw Payload Inspector: Displays the decoded string/JSON encoded in the QR code (UDIN, GSTIN, issuing CA membership number, declared figures, timestamp).
  • Side-by-Side Discrepancy Matrix: Explicitly highlights discrepancies between printed text and embedded QR data with color-coded mismatch tags.
  • Live Phone Camera Scanning: Incorporates a live scannable QR display directly within the UI, allowing procurement officers and vigilance committee members to scan the code with their personal smartphones to independently verify raw portal payloads.
  • Live GeM QR Generator: Allows officers to generate authentic, cryptographically signed test QR payloads to simulate and stress-test vendor verification workflows.
